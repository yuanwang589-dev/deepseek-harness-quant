> 目的：针对本项目当前**已核实的具体缺口**去找可借鉴的开源项目，不是泛泛列量化框架。

## 1. `VernonOY/alpha-skills` —— 架构同构，最该抄的一个

**119★ · Apache-2.0 · 2026-10-12 活跃**

**为什么它排第一**：这个项目跟我们的架构**几乎同构**——都是"AI 编程助手 + 一组 SKILL.md + SQLite 因子库"。
它把因子研究拆成 **9 个 skill**，正好是我们 `assets/skills/` 该长的样子：

```
skills/
  alpha-discover   从自然语言设计因子
  alpha-evaluate   IC / ICIR / 五分位 / 多空 / 鲁棒性
  alpha-mine       自动挖候选因子 → IC 快筛 → 排序
  alpha-library    注册/查看/搜索/退役因子（SQLite）   ← 对应我们的 factor_pool
  alpha-monitor    检测 IC 衰减 / 拥挤 / regime shift  ← 正是我们缺的
  alpha-report     全景/深挖/对比报告
  alpha-signal     每日交易信号 → 目标组合
  alpha-backtest   单因子 & 多因子组合回测
  alpha-autopilot  mine → evaluate → register → monitor → retire 自动闭环
```

### 1.1 可直接借鉴的三处

**① 因子表字段比我们全**（`alpha-library` 的建表语句）

```sql
CREATE TABLE factors (
  id TEXT PRIMARY KEY, name TEXT UNIQUE NOT NULL,
  expression TEXT NOT NULL,          -- ★因子表达式（我们没存）
  category TEXT, description TEXT,
  status TEXT DEFAULT 'active', market TEXT DEFAULT 'A-share',
  ic_mean REAL, icir REAL,            -- ★实测 IC 指标（我们只存单一 score）
  best_holding_period INTEGER,        -- ★最优持有期
  quality TEXT, eval_date TEXT,
  created_at TEXT DEFAULT CURRENT_TIMESTAMP, metadata TEXT)
```

对比我们的 `factors` 表：有 `family/kind/source/direction/status/score/note`，
**缺 `expression`（因子怎么算）、`ic_mean`/`icir`（实测指标）、`best_holding_period`（最优持有期）**。
这正是"有池无序列"的另一个侧面——我们连"这个因子怎么算出来的"都没存。

**② L0–L3 四级评估流水线**——直接解决我们的"评估慢"

| 级别 | 内容 | 耗时 |
|---|---|---|
| L0 | 语法 + 数据校验 | 即时 |
| **L1** | **抽样快筛（200 股 × 2 年）** | **< 30s** |
| L2 | 全量：IC 序列、ICIR、五分位、多空、单调性 | 1–3 min |
| L3 | 鲁棒性：参数扰动、滚动窗口、起始日敏感性 | 5–15 min |

我们的 `factor_evaluator` 只有"全量"一档，所以 6 个因子要跑 20+ 分钟。
**分级是解法**：先用 L1 抽样把明显无效的因子筛掉，只对通过的做全量。

**③ 过拟合护栏：economic intuition score**

每个存活因子都要给一个"经济学直觉分"（Strong / Moderate / Weak），
**没有清晰行为逻辑的因子被标记为疑似数据挖掘**。
我们的 `STRONG_TABLE` 有 `f3_family`（族）和 `style_exposed`（风格暴露），但**没有"有没有故事"这一维**。

### 1.2 还有一处值得注意

它引用了 **`VernonOY/qtype`**——"static analysis to catch look-ahead bias before you waste compute on fake alpha"，
即**在算之前用静态分析抓前视偏差**。我们项目反复强调"T+1 无前视"，这个思路值得单独看。

## 2. `eliasswu/AlphaPurify` —— 解决"评估慢"

**587★ · MIT · 2026-10-15 活跃**

- **Polars + Rust 向量化 + 多进程**，宣称 **400 万行（15 年 CSI300）跑完多空/多空对冲/IC 回测 + 生成 4 个交互报告 < 25 秒**（i7）
- 四个模块：`FactorAnalyzer`（IC/RankIC + 分层多空回测）、`AlphaPurifier`（**40+ 预处理**：去极值/中性化/标准化，含 ridge/lasso/PCA）、`Database`（因子构建与存储）、`Exposures`（因子相关性 + 收益归因）
- 官方对比表里明确说 Qlib "Slow (heavy infrastructure)"，自己主打"零拷贝、OOM 保护、截面快照原生"

**借鉴价值**：它的**中性化方法库（40+）**是我们完全没有的。
我们的 `factor_risk.py` 有家族归并和 FDR，但**没有系统的去极值/中性化/标准化**——
而 `STRONG_TABLE` 里已经标了 `style_exposed`（F4 双中性），说明我们知道需要中性化，只是没实现。

**注意**：引入 Polars 与项目"零第三方依赖"的测试约定冲突（`tests/` 只用标准库）。
建议只**借鉴方法**（去极值用 MAD、中性化用截面回归），不引入依赖。

## 3. `JustinF8/qlib-factor-zoo` —— 解决"因子数量"

**17★ · MIT · 2026-10-13**

六大因子库，**共约 1013 个因子**，专为 A股优化：

| 因子库 | 因子数 | 来源 |
|---|---|---|
| Alpha360 | 360 | Qlib 原生（量价回溯 60 日） |
| Alpha158 | 158 | Qlib 原生（K线形态 + 滚动统计） |
| Alpha101 | 101 | WorldQuant 101 公式化 Alpha |
| GTJA191 | 191 | 国泰君安 191 短周期交易 Alpha |
| TDXGS | ~90 | 通达信/同花顺（MACD/KDJ/RSI/BOLL…） |
| JQ110 | ~113 | 聚宽（动量/情绪/技术/风险/风格） |

还提供 **`custom_ops.py` 的 50+ 自定义算子**（趋势/波动/超买超卖/量价关系/人气/通道）。

**借鉴价值**：我们卡在"本仓能算的因子只有 22 个"。这里的因子定义是**公式化的**（表达式），
不需要 qlib 全套基础设施也能抄定义——尤其 **GTJA191** 和 **TDXGS** 是纯价量，我们 `bars.db` 的
`close/volume/turn/amount/high/low` 完全够算。

**注意**：项目本身是 qlib 的 fork，直接安装会替换 qlib；但**只抄因子公式**没问题（MIT）。

## 4. `1nchaos/adata` —— 解决"数据缺失"

**5278★ · Apache-2.0 · 2026-10-15 活跃**

免费开源 A股数据库，多数据源融合（同花顺/百度/东方财富/腾讯/新浪）。

**直接命中我们缺的东西**：

| 我们缺的 | adata 对应接口 |
|---|---|
| `lhb_full.db`（龙虎榜） | `sentiment.hot.list_a_list_daily()` / `sentiment.hot.get_a_list_info()` |
| `rzrq_full.db`（两融） | `sentiment.securities_margin()`（全市场融资融券余额） |
| **`ind_moneyflow`（§6.4 里 event 类型缺的行业资金流）** | `stock.market.get_capital_flow()`（个股资金流历史）、`stock.market.all_capital_flow_east()`（**概念资金流近 1/5/10 日**） |
| `stock_basic.industry` 不够规范 | `stock.info.get_industry_sw()`（**申万一二级行业**） |
| 换手率口径 | `stock.info.get_stock_shares()`（股本信息） |
| 分钟数据 `minute.db` | 只有**当日分时**（`get_market_min`），历史分钟线**不提供** |
| 股东户数 `gdhs_full.db` | **不提供** |

**⚠️ 三个必须注意的点**：

1. **它是在线接口，不是本地库**。数据靠爬公开接口，有频率限制、需要代理设置
   （`adata.proxy(is_proxy=True, ip=...)`）。这与我们"零端口暴露的本机部署"不冲突
   （只做出站请求），但**数据落地要自己做**。
2. **官方自己声明**：财务数据"只做股票池筛选作用，不做实时交易指标推荐"，
   理由是"财务数据相对滞后，而且可能造假"。这对我们 Beneish 降级版的定位是个呼应。
3. **股东户数（`gdhs_full.db`）它没有**——那个缺口得另找（Tushare 有，但需积分）。

## 5. `cn-vhql/FactorHub` —— A股因子平台，但**无许可证**

**430★ · ⚠️ 无 LICENSE · 2026-10-12 · Python**

功能最贴我们的**因子池设计**：完整的因子生命周期管理（创建→验证→分析→部署）、
IC/IR 分析（1/5/10 日预测周期）、**因子动态监控（时序表现追踪）**、遗传算法挖因子（DEAP）、
因子归因、以及**因子版本控制（修改历史 + 版本回滚）**。
支持**通达信公式语法（MyLanguage）+ TALib**，有内置因子库。

**⚠️ 许可证警告**：仓库**没有 LICENSE 文件** → 默认"保留所有权利"。
**不能抄代码，只能读它的设计思路**（尤其"因子版本控制"这一条，我们的池没有版本概念，
`register()` 是直接 UPDATE，改了就是改了，没有历史）。

## 6. `warren618/AlphaForge` —— 因子组合与统计严谨性

**37★ · MIT · 2026-10-14**

结构清晰（虽然是加密永续，但**因子流水线是通用的**）：

```
src/factor_pipeline/
  factors/         你的因子实现（可插拔）
  evaluator.py     Rolling IC + FDR + Newey-West t
  combo_search.py  贪心前向搜索找最优因子组合
  registry.py      decorator 自动发现因子
  pipeline.py      CLI 编排
```

**三处值得借鉴**：

1. **FDR 校正 + Newey-West t 统计**——我们 `factor_risk.py` 有 FDR（BH q=0.05），
   但没有 **Newey-West 调整**（时序自相关会让 t 值虚高）。
2. **贪心组合搜索**——我们的 `pv_consensus` 是**手工设阈值**（"五强 rank 前 20% 命中 ≥4"）。
   自动搜索"哪几个因子组合起来 IC 最高"是更系统的做法。
3. **`registry.py` 用 decorator 自动发现因子**——我们 `FACTOR_FUNCS` 是手写字典
   （文档 §2 已更正过"注册即自动接入"的虚假声称）。decorator 模式可以真正实现"注册即接入"。

## 7. 组合层风控（我们完全没有）

| 项目 | 星 | 许可 | 能借什么 |
|---|---|---|---|
| **`dcajasn/Riskfolio-Lib`** | 4542 | BSD-3 | 风险平价、**HRP 层次风险平价**、集中度约束、多种风险度量 |
| **`PyPortfolio/PyPortfolioOpt`** | 6098 | MIT | 有效前沿、Black-Litterman、HRP、**权重上下限约束** |
| `convexfi/riskparity.py` | 325 | 待查 | 快速可扩展的风险平价构建 |

对应 §9.5 的三条缺口（无集中度上限、无波动率目标仓位、无体制过滤）：
- **集中度上限** → PyPortfolioOpt 的 `weight_bounds` / Riskfolio 的约束 API
- **波动率目标仓位** → 风险平价 / HRP 直接给权重，替掉现在的"等权整手"（30% 现金闲置的根源）
- **体制过滤** → 这两个库不管，得自己做（可用我们已有的 L0 择时分数）

**注意**：都依赖 `cvxpy`/`scipy`，与"零第三方依赖"测试约定冲突。建议**借鉴算法自己实现**
（HRP 的核心就是相关性聚类 + 递归二分，几十行）。
